# Российские сервисы мимо VPN

Первый тумблер экрана исключений включает общий режим для приложений. По умолчанию выключен. Ручные списки сайтов и приложений, включая ЧС/БС, сохраняются; при включении обхода они недоступны и не участвуют в маршрутизации. Выключение возвращает сохранённые настройки.

## Получение и применение списка

После готовности основного WDTT/WireGuard клиент получает `GET /api/vpn/routing-policy` через локальный native relay `127.0.0.1:18766`. Relay использует существующий WireGuard device и служебный адрес `10.66.66.1:8000`. В его allowlist добавлен только этот точный GET; записи в API и остальные endpoint по-прежнему запрещены. Ответ должен иметь HTTP200 и `X-Silent-Upstream: 1`. Проверяются схема, revision, размер и домены.

Ни второй VPN/peer, ни payment overlay для чтения не создаются. Новый список передаётся в работающий router по stdin с ожиданием POLICY_READY. Это обновление сохраняет WG/TUN и открытые соединения приложений. Само переключение режима может менять политику приложений/браузеров и требовать пересоздания TUN.

Зелёное «Список получен» означает успешную загрузку с сервера и подтверждённое применение в текущем router. Ответ с той же revision тоже считается полученным; один сохранённый или встроенный кеш успехом не считается. После ошибки сохраняется предыдущая политика, отображается ошибка, повтор — через10с. Успешная фоновая проверка повторяется через300с. Переключение режима будит задачу немедленно, без постоянного секундного таймера в рабочем состоянии. Запоздалый ответ после OFF не заменяет кеш.

При выключенном VPN показано ожидание подключения. Отдельный bootstrap только ради списка не запускается. Существующие auth/payment/promo-механизмы не меняются.

## Маршрутизация

VPN-правило имеет приоритет над DIRECT, включая общий суффикс ru. Служебная сеть 10.66.66.0/24 остаётся в VPN. При ошибке загрузки применяется последний корректный кеш или встроенный снимок. Серверные списки этим исправлением не меняются.

После неуспешного candidate3 alias-реализация снята; текущий router основан на pre-v3/v2. Он классифицирует полученные DNS-адреса, имеет защиту служебных адресов и VPN overrides. Собственный DoH/DoT и жёстко заданные адреса приложений не дают доменных DNS-ответов для классификации. Доставка списка не является отдельным исправлением всех ограничений классификации общего CDN.
