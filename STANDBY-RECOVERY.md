# Резервный API на сотах

Обычный запрос идёт к Улью. Сота отвечает из защищённого снимка при сетевой ошибке или HTTP 5xx. Ответы 401/402/403/429 Улья сохраняются. После существующего порога из трёх неудачных health-проверок готовый локальный ответ не ждёт повторного таймаута upstream. Порог и логика DNAT не изменены.

Работают вход существующего аккаунта по паролю, получение конфига зарегистрированного активного устройства, обновление сохранённого сеанса, выбор доступного сервера, чтение профиля и хешей. Подписка, владелец устройства, запрет административного сервера и минимальная версия ИИ-сервера проверяются по снимку. Новая регистрация, новое устройство, изменение аккаунта и платежи требуют Улья. Рабочий VK/TURN и доступная выбранная VPN-нода по-прежнему нужны.

Снимок обновляется примерно раз в минуту и имеет абсолютный срок действия один час по времени Улья. Репликация/разница часов могут влиять на наблюдаемый возраст. Отзыв доступа отражается следующей успешной синхронизацией; при полном разрыве связи резерв перестаёт принимать снимок по истечении срока. Это ограниченный режим восстановления, а не бессрочная независимая база пользователей.

Ключ JWT Улья не копируется на соты. Улей заранее подписывает короткие токены с областью `vpn-recovery-v1`; центральный API запрещает ими изменения аккаунта, админку и создание нового устройства. Refresh такого токена не снимает ограничение и не продлевает абсолютный срок. При offline refresh существующего обычного сеанса сохраняется исходный refresh клиента: после восстановления Улья он может продолжить обычную авторизацию без принудительного выхода.

Старые JWT распознаются по SHA256-реестру токенов, ранее проверенных центральным API. Реестр наполняется на обычных запросах и выдаче токенов, асинхронно, без задержки пользовательского ответа. **Ранее не встреченный токен при недоступности Улья получает 503, не 401:** нельзя разрешать доступ по неподтверждённому JWT или разлогинивать старого клиента. Сохранённый конфиг клиента и вход по паролю остаются путями восстановления. Начальное покрытие старых сеансов увеличивается по мере их обычных обращений к Улью.

Каждая сота получает отдельный Fernet-ключ через SSH в `/etc/wdtt/standby_api.key` с правами 0600. Копия ключа в AppSetting зашифрована секретом backend; manifest содержит только ciphertext. Снимок включает чувствительные данные для восстановления: bcrypt-верификаторы, ключи устройств и короткие токены. Не публиковать расшифрованное содержимое или ключи в логах/артефактах.

`standby_api.py` не запускает wg/iptables, не перезапускает wdtt и не меняет passwords.json. Список peer-устройств прежнего manifest не расширяется. Формат конфига прежний, MTU/DNS/порт берутся из профиля выбранной ноды, stream_count остаётся 9. Неизменённый WDTT GETCONF выдаёт локальную транспортную WG identity, как при обычном подключении.

## Порядок обновления

1. `python scripts/rollout_standby_api.py prepare` — добавочная таблица, отдельные ключи, lease автообновления агентов на 30 минут. Функция не включает резервный API.
2. `python scripts/rollout_standby_api.py validate` — реальная сборка снимка в транзакции `READ ONLY`.
3. Python backend публикуется только `scripts/deploy_stable.py --python-only ...`; текущий manifest feature по умолчанию выключен. Скрипт выполняет preflight и проверяет реальные source/mounts.
4. `python scripts/deploy_stable.py --cell-agent-source-only` — только bundle агента на хост Улья, без рестарта API/nginx. Требуется активный lease; он исключает одновременный auto-upgrade всех сот.
5. `python scripts/rollout_standby_api.py cell --slot serverN` — по одной соте: backup, upgrade только агента, ожидание реально работающей версии, включение снимка, изолированный ASGI outage-test. Проверяются WDTT PID/NRestarts, ifindex, живые AllowedIPs и DNAT. При ошибке возвращаются предыдущий агент и выключенный feature этой соты. WDTT не перезапускается.
6. `python scripts/rollout_standby_api.py accept` — обычный JWT проходит центральный verifier, hash-реестр и настоящий manifest; на каждой соте проверяется локальное принятие при изолированном отказе proxy. Затем наблюдается health API во время обновления снимков.
7. `python scripts/rollout_standby_api.py release` — только после совпадения build_id и готовности снимков всех активных сот; снимает lease.

Ключ `standby_offline_cells_v1` включает feature отдельно по UUID соты. `standby_agent_rollout_hold_until` — временный lease, не постоянное отключение auto-upgrade.

## Отключение резерва

`python scripts/rollout_standby_api.py disable --slot serverN` выключает одну соту; без `--slot` — все. Публикуется обычный peer manifest без encrypted API, VPN/агент не перезапускаются. Проверить `manifest_delivered`: если сота недоступна, старый снимок сам истечёт через ограниченный срок. Ключи и таблица остаются для обратного включения. Не чистить живые WG-пиры и не рестартить WDTT для отката этой функции.

Проверки: `python scripts/test_standby_api_unit.py` и штатный deploy preflight. Реальный отказ сети/VPN на production не создаётся: отказ proxy имитируется в отдельном процессе на копии действующего кода и настоящем зашифрованном снимке. Полевое переподключение физического телефона при реальном отказе Улья отдельно не проверялось.
