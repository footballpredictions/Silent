# Российские сервисы мимо VPN — Windows, Linux, macOS

Первый тумблер исключений включает глобальную серверную политику DIRECT/VPN для всех приложений. Ручные приложения и сайты, ЧС/БС сохраняются в своих прежних файлах. Пока режим включён, эти элементы недоступны, их изменения отклоняются IPC, ручные фоновые обходы остановлены. Выключение восстанавливает сохранённые списки.

Состояние и последний корректный кеш хранятся отдельно в userData/russian-services.json. Публичный GET `/api/vpn/routing-policy` проверяется по схеме, revision, размеру и допустимым суффиксам; при недоступности остаётся кеш или встроенный снимок. Начальное значение OFF сохраняет совместимость. Периодическое обновление не перезапускает WG; неизменная политика не закрывает длинные соединения. Состояние повторно сверяется после подключения, чтобы переключение во время запуска не потерялось.

Системный DNS российских доменов обслуживается через WAN, соответствие IP устанавливается до ответа приложению. VPN override выше DIRECT даже на общем IP; служебная подсеть и DNS-потоки сохраняют VPN. IPv6/HTTPS/SVCB-подсказки DIRECT-доменов подавлены в пользу IPv4. Собственный DoH/DoT и заранее заданные IP не позволяют классифицировать назначение по домену и остаются в VPN.

Windows использует native-маршрутизатор через Wintun. Linux/macOS собирают тот же пакетный маршрутизатор как `wireguard-go`: существующий root-helper настраивает TUN/utun и WireGuard через прежний UAPI. DIRECT-сокеты привязаны к физическому интерфейсу через SO_BINDTODEVICE / IP_BOUND_IF. Политика обновляется через отдельный root-only Unix-сокет с подтверждением без замены VPN-процесса.

В режиме ON системный DNS направлен на внутренний адрес `10.66.66.53`. Российские UDP DNS-запросы обрабатываются через WAN до ответа приложению; остальные DNS-пакеты преобразуются к первому выбранному IPv4-резолверу и проходят через WireGuard. Обратное преобразование сохраняет ожидаемый приложением адрес DNS, включая TCP/UDP checksum и фрагменты. Это локальный адрес обработчика, отдельный DNS-сервис на сервере VPN не требуется. OFF возвращает прежний системный DNS и ручные исключения. Bootstrap сохраняет прежнюю область маршрутов.

Для Linux необходима переустановка нового `.deb`, который обновляет системный helper. На Mac `./build-mac.sh` собирает новый обработчик для обеих архитектур; при первом подключении после замены приложения обновление устаревшего helper может запросить пароль macOS один раз. Сборка и проверка настоящего utun требуют Mac.

Mac `protect-on` обеспечивает физический default с `-ifscope <LAN interface>`: одного `IP_BOUND_IF` недостаточно, если такого scoped-маршрута нет. Созданный приложением маршрут записывается в `lan-protect.json`, проверяется при обновлении защиты и удаляется при отключении. Уже существующие scoped-маршруты сохраняются, другой шлюз не перезаписывается. Подтверждённый на Mac отказ до исправления: RU DNS SERVFAIL, привязанные WAN-сокеты errno51/65 при рабочем DNS роутера; добавление scoped default восстановило RU DNS и HTTPS без перезапуска VPN.

OpenWrt/Keenetic используют собственные переключатели; их пакеты здесь не менялись.

Проверки 2026-10-16: Node 176 PASS / 1 SKIP, native Go 30 PASS, затем 20 интеграционных проверок после финальной синхронизации подключения. Проверены настоящий IPC, сохранность обоих файлов, серверный кеш, общая маршрутизация без поиска владельца процесса, приоритет VPN и сохранение длинного TCP. Экран проверен в браузере при штатной ширине 265 px: все ручные controls недоступны при ON, список возвращается после OFF, горизонтального overflow нет.
