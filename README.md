# Silent VPN для Keenetic — 1.0.169

Отдельный порт клиента для KeeneticOS + Entware. В архиве собственный агент, встроенная веб-панель Silent, наш VK/WDTT-транспорт `spass` и WireGuard userspace. Сервер использует прежний API, `device_type=pc`, имя устройства `Keenetic <hostname>`. Старые клиенты и сервер не требуют изменений.

Статус: локальная сборка и проверки. Реальная установка/работа на Keenetic пока не подтверждены. «Универсальная» означает варианты CPU с проверкой требований, а не гарантию для каждой модели/прошивки.

## Архитектуры

Универсальный `dist/silent-vpn-keenetic-1.0.169.tar.gz` содержит aarch64, ARMv7, ARMv5, MIPS little endian, MIPS big endian, x86_64 и i386. Есть меньшие отдельные архивы для каждого CPU. MIPS выбирается по ELF byte order `/bin/sh`, не только по `uname`; ARMv6 использует совместимый ARMv5 вариант. Статические бинарники: CGO отключён, musl/glibc не нужны.

## Требования

- KeeneticOS с настроенным Entware на USB EXT4 или поддерживаемом внутреннем NAND-разделе. На моделях без такой среды клиент не устанавливается.
- Linux 3.2+, EPOLL/FUTEX; `/dev/net/tun` и рабочая поддержка TUN ядром. При необходимости установите компонент OpenVPN/IPsec через KeeneticOS; создание device node само по себе не добавляет драйвер.
- Root shell Entware, `ip-full`, `ipset`, `iptables`/`ip6tables`, поддержка MARK, DNAT, MASQUERADE, conntrack и ipset ядром, включённый IPv4 forwarding. Установщик проверяет часть требований до запуска; остальные проверяются при подключении с очисткой частичных правил.
- Свободное место под два выбранных бинарника и конфигурацию: ориентир 45 МБ плюс распаковка/backup. Для универсального архива и распаковки желательно от 300 МБ свободного места на накопителе. Не используйте /opt/tmp без проверки: он может ссылаться на RAM /tmp. Универсальный архив распаковывайте на накопитель Entware; для малого хранилища используйте архив выбранной архитектуры. Свободную RAM и скорость необходимо проверить на устройстве, userspace WG и VK-транспорт требуют CPU/RAM.
- Основной частный IPv4 LAN bridge, по умолчанию `br0` (fallback `br-lan`). Только его клиенты проходят через VPN. Для другого bridge задайте `SVK_LAN_INTERFACE`; гостевые сети отдельно не захватываются.
- Собственные таблица 20513, приоритеты policy rules 51/52, mark `0x53000000/0xff000000`, имена интерфейса `svkeen`, цепочек `SVK_*`, ipset `svk_direct` должны быть свободны. Не устанавливайте поверх конфликтующих Entware VPN/перехватчиков без проверки.

## Установка

Скопируйте выбранный архив на накопитель роутера и выполните в Entware shell:

```sh
mkdir -p /opt/share/silent-keenetic-install
cd /opt/share/silent-keenetic-install
# Скопируйте архив в эту папку перед распаковкой.
tar -xzf silent-vpn-keenetic-1.0.169.tar.gz
cd silent-vpn-keenetic-1.0.169
sh install.sh
```

Установщик ставит зависимости через Entware OPKG. Если они уже подготовлены: `sh install.sh --no-deps`. Другой основной bridge: `SVK_LAN_INTERFACE=br0 sh install.sh`.

После первой установки отображаются адрес `http://<LAN-IP>:8787`, локальный логин `admin` и случайный пароль панели. Затем внутри панели войдите в аккаунт Silent VPN, выберите сервер и подключитесь. Порт управления Keenetic не занимается. Для доступа к панели разрешены клиенты выбранного LAN, включая Wi-Fi; пароль панели отличается от пароля аккаунта. HTTP используется внутри доверенного LAN.

Настройки и токены: `/opt/etc/silent-keenetic/config.json`, права 0600. Не пересылайте файл целиком — в нём секреты. Здесь можно изменить LAN/порт/пароль, затем перезапустить сервис. При обновлении конфигурация сохраняется, предыдущий runtime/config копируются в `/opt/var/backups/silent-keenetic-*`.

```sh
/opt/etc/init.d/S99silent-keenetic status
/opt/etc/init.d/S99silent-keenetic stop
/opt/etc/init.d/S99silent-keenetic start
/opt/lib/silent-keenetic/silent-keenetic --check
```

## Маршрутизация, DNS и восстановление

Транспорт идёт через WAN; WG разговаривает с ним только на `127.0.0.1:9000`. Клиент сначала получает свежий `wg-turn.conf`, дожидается WG handshake и доступности шлюза, проверяет `/api/vpn/connect`, затем включает захват LAN. Отказы 401/402/403 не обходятся переключением API. Main default и настройки WAN не меняются; в main добавляется только маршрут `/32` до шлюза туннеля. Чужие VPN, DHCP и системный DNS не перезапускаются.

DNS прокси на LAN:15353 принимает перенаправленные LAN UDP/TCP53. Обычные запросы идут через туннель, выбранные российские домены — через WAN DNS Яндекса `77.88.8.8/77.88.8.1`; их A-ответы добавляются в частный ipset до ответа клиенту. Список взят из актуального OpenWrt, включает Flashscore/Школково/MAX/WB/Ozon. Learned IP сохраняются до отключения, без таймера, который конфликтовал бы с DNS-кешем. Общий IP CDN может расширить обход; DoH/DoT/жёстко заданные IP не дают достоверного доменного исключения.

VPN пока IPv4: AAAA подавляются, IPv6 forwarding выбранного LAN блокируется на время подключения, чтобы не обходить VPN. IPv6 к самому роутеру не блокируется. После отключения собственные правила удаляются.

NDM netfilter hook восстанавливает только свои цепочки изменённой таблицы, без reconnect в общей очереди NDM. Supervisor очищает собственные маршруты/DNS-правила после падения агента и запускает его повторно. Последнее успешно подключённое состояние восстанавливается после перезагрузки; явное отключение убирает автоподключение. Три последовательных сбоя health (~60 с) отключают туннель и возвращают обычный интернет; автоматическое повторное подключение после этих health-сбоев не выполняется. Это поведение fail-open, строгого kill switch нет.

## Что проверить на реальном Keenetic

1. Запуск CPU-варианта, `--check`, доступность панели по кабелю/Wi-Fi.
2. Handshake, внешний IP клиента LAN, достижимость интерфейса управления Keenetic во время VPN.
3. DNS UDP/TCP, RU direct, YouTube/Telegram через VPN; IPv6 не уходит напрямую.
4. Отключение, перезагрузка, падение агента, восстановление NDM правил при WAN-событиях.
5. FastNAT/PPE, уже открытые соединения, другие политики Keenetic/Entware и скорость.

Ускорение FastNAT/PPE может обходить policy/netfilter для части потоков. Клиент не выключает ускорение глобально и не сохраняет изменённую конфигурацию Keenetic. До реальных испытаний не обещайте захват всего трафика или конкретную скорость. Подробности и первичные источники, включая предоставленную тему 4PDA: [RESEARCH.md](RESEARCH.md).

## Удаление

```sh
sh /opt/lib/silent-keenetic/uninstall.sh
# При необходимости удалить также аккаунт/настройки с роутера:
sh /opt/lib/silent-keenetic/uninstall.sh --purge
```

Первый вариант сохраняет конфигурацию. Удаляются только пути и правила Silent Keenetic; зависимости Entware и чужие службы остаются.

## Сборка из проекта

```sh
python keenetic/scripts/build.py
# Один вариант:
python keenetic/scripts/build.py --target mipsel
```

Go 1.26.2+, исходники `pc/wdtt-go` рядом. Собственные зависимости агента закреплены в `agent/go.mod` и `go.sum`. Скрипт реально компилирует каждый вариант, проверяет ELF architecture/endianness, собирает отдельные/универсальный архивы и `dist/SHA256SUMS`, `manifest.json`. Публикация и установка на роутер — отдельные действия. Дизайн панели сохранён из нашего OpenWrt; исходный OpenWrt проект не изменяется.
