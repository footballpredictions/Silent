# Профили узлов

В админке «Улей» у каждого сервера, включая главный, доступны независимые
профили «Для ИИ» и «Игровой». Их можно совмещать. Существующие роли, выбор
сервера устройствами и ограничения старых клиентов не меняются.

«Для ИИ» нормализует TTL клиентского IPv4 и выдаёт новым подключениям DNS
Cloudflare. Глобальный фильтр угроз и явно выбранный пользователем DNS имеют
приоритет. Системный DNS хоста, служебные порты, WARP и прокси не переключаются.
Репутация IP и доступность конкретного ИИ-сервиса от этого не гарантируются.

«Игровой» включает PMTU/TCPMSS и увеличивает UDP conntrack timeouts, если
существующие значения меньше. MTU серверного wdtt0 только повышается до 1420.
Рекомендованный клиентский MTU приходит в необязательном поле `wg_mtu`
конфига VPN. DNS и новый клиентский MTU применяются при следующем обычном
подключении; принудительного переподключения нет.

Старые клиенты сохраняют свою политику MTU. Обновлённые Android, Windows/Linux
и iOS принимают серверную рекомендацию с проверкой диапазона. Mac сохраняет
проверенный MTU 1280; роутеры сохраняют обычный MTU 1280 и принимают игровой 1420.
Bootstrap не наследует игровой MTU основного подключения.

## Безопасность переключения

`PATCH /api/admin/hive/cells/{uuid}/profiles` принимает `ai`, `gaming` и
`expected_revision`. Требуется обычная админская авторизация. Оба профиля
опциональны, но хотя бы один должен быть указан. Устаревшая ревизия или
незавершённая операция возвращает 409.

Состояние хранится в `AppSetting` с ключом `node_profiles:{uuid}`. PostgreSQL
блокирует строку только на время резервирования операции и записи результата.
Во время SSH/проверок соединение БД не удерживается. Флаги отражают последнюю
подтверждённую настройку; желаемые значения видны отдельно в `requested`.

Операция выполняется отдельным systemd-процессом на целевом хосте. Улей
использует существующий `silent-nsenter`; соты — сохранённый SSH. Пароль Улья
в БД для этого не нужен. Каждый хост имеет файловую блокировку, журнал и
отдельный таймер восстановления; потеря SSH или перезапуск API не обрывает
хостовую операцию. Фоновое восстановление API согласует её результат с БД.

Перед применением и после него проверяются API health, PID wdtt и сохранность
живых WG peers. Новые правила имеют метку `SILENT_NODE_PROFILE_*`. При ошибке
восстанавливаются собственные правила и изменённые sysctl; конкурентные
изменения других инструментов не перезаписываются. Успешная конфигурация
восстанавливается после загрузки через `silent-node-profiles.service`.

Никогда не выполняются restart/stop wdtt, замена WG peers, flush iptables или
conntrack, изменение API DNAT либо смена системного DNS. При выключении
игрового профиля MTU живого серверного интерфейса и UDP timeouts не снижаются:
это сохраняет работающие подключения, включая старые клиенты с MTU 1420.
Совместимый предел MTU также сохраняется для последующих загрузок узла.

## Существующие установки

Без записи AppSetting начальные значения берутся из прежней конфигурации:
`ai_exit` означает существующий ИИ-профиль, Сота 2 / прежний игровой IP —
игровой профиль. Сам по себе деплой ничего на сотах не переключает.

`HiveCell.ai_exit` остаётся старой ролью маршрутизации и безопасности:
ограниченный agent-порт, исключение из standby, гейт старых клиентов.
Новые профили хранятся отдельно, поэтому включение ИИ на обычной соте или
Улье не лишает клиентов API и не скрывает выбранный сервер.

При снятии старого ИИ-профиля удаляются только его DNS DNAT на :5353 и
отключаются старые задания повторного применения. DNS-процессы и остальные
правила гигиены сохраняются; установленные соединения не сбрасываются.
Снятие при работающем отдельном legacy-прокси отклоняется: сначала нужен
контролируемый вывод этого прокси, чтобы не оборвать его TCP-соединения.

## Проверки

Для браузерных проверок сначала `cd admin-ui && npm ci`, затем
`npm run dev -- --port 3012`. Нужен установленный Chrome; Playwright закреплён
в devDependencies. Скрипты ниже запускаются из каталога backend.

- `python scripts/test_node_profiles_unit.py` — комбинации профилей, откат,
  сохранность общих правил, живого MTU и более длинных UDP timeouts.
- `node scripts/test_hive_profiles_ui.cjs` при запущенной админке на 3012 —
  все узлы, Улей без SSH, pending, откат, конфликт, offline и мобильная ширина.
- `python scripts/test_hive_profiles_db.py --run --http` в API-окружении —
  настоящий PostgreSQL, конкурентные запросы, ревизии, устаревшие задания,
  реальный HTTP-обработчик и авторизация. Используются только случайные
  временные AppSetting-ключи; никаких HiveCell/device или хостовых изменений.

Деплой: только `scripts/deploy_stable.py` с явным выбором изменённых Python-файлов
и `--with-admin-ui`. Публикация клиентских сборок выполняется отдельно.

Перед точечным деплоем проверяются единственный рабочий API-контейнер,
правильные read-only bind mounts и совпадение 17 критичных модулей с локально
проверенными исходниками. Для явно выбранных файлов совпадение проверяется
после загрузки; остальные должны совпасть до неё. CRLF и лишние пустые строки
в конце не считаются другой версией кода. Результат сохраняется в закрытом
файле `.deploy-manifest.json` на хосте. Остановленный API остаётся ремонтопригодным:
в таком случае проверяется источник его bind mounts, затем — запущенный контейнер.
